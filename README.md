# CCHAT — консольный мессенджер на C

Небольшой клиент-серверный мессенджер без внешних библиотек (кроме pthread).
Есть аккаунты, общий чат, шифрование трафика и шифрованные файлы истории на
сервере и у клиента.

## Возможности

- регистрация и вход по нику и паролю;
- пароли хранятся на сервере только как PBKDF2-HMAC-SHA256 хеши с солью;
- весь сетевой трафик шифруется (ChaCha20 + HMAC-SHA256, encrypt-then-MAC);
- сообщения сохраняются на сервере в зашифрованном текстовом файле;
- клиент сохраняет свою копию истории в зашифрованном текстовом файле;
- просмотр истории без входа в чат, в том числе в отдельном терминале;
- история разбита на куски по 100 сообщений, показываются доступные куски;
- несколько клиентов могут общаться в одном общем чате одновременно.

## Требования

- Linux (используются POSIX-сокеты, pthread, termios);
- `gcc`;
- `make` (необязательно, можно собрать двумя командами gcc вручную).

## Быстрый старт

1. Склонируйте репозиторий и перейдите в его каталог.

2. Откройте `server.c` и `client.c`. В обоих файлах задан общий секрет:

   ```c
   #define SHARED_SECRET "CHANGE-ME-cchat-shared-secret-please-32-bytes-minimum"
   ```

   Замените строку на свой длинный случайный ключ. **Ключ должен быть
   одинаковым в `server.c` и `client.c`.** Порт тоже задаётся в `.c`:

   ```c
   /* server.c */
   #define SERVER_PORT 5555

   /* client.c */
   #define DEFAULT_PORT 5555
   ```

3. Соберите сервер и клиент:

   ```sh
   make
   ```

   Либо напрямую через gcc:

   ```sh
   gcc -O2 -std=c11 -pthread -o cchat-server \
       server.c crypto.c net.c history.c util.c

   gcc -O2 -std=c11 -pthread -o cchat \
       client.c crypto.c net.c history.c util.c
   ```

4. Запустите сервер:

   ```sh
   ./cchat-server
   ```

   Сервер создаст каталог `data/`, файл аккаунтов и зашифрованный журнал чата.
   Порт по умолчанию — `5555`; при необходимости разрешите его в firewall.

5. В другом терминале запустите клиент:

   ```sh
   ./cchat
   ```

## Работа с клиентом

Главное меню:

```text
0) Добавить сервер по IP
1) Название добавленного сервера (ip:port)
...
h) Прочитать историю чата
q) Выход
```

- `0` — добавить сервер. Нужно ввести IP/домен, название и порт
  (по умолчанию берётся `DEFAULT_PORT` из `client.c`). Список серверов
  сохраняется в `~/.cchat/servers.tsv`.
- Номер сервера — выбрать сервер из списка.
- `h` — перейти к просмотру истории. Будет предложено ввести номер сервера.

После выбора сервера:

```text
1) Войти в чат
2) Присоединиться (создать аккаунт)
3) Прочитать историю этого сервера
0) Назад
```

- `1` — вход: никнейм и пароль.
- `2` — регистрация: никнейм, пароль и повтор пароля.
- `3` — локальная история выбранного сервера.

В чате вводите сообщение и нажимайте Enter.

```text
/quit  или /exit — выйти из чата
/help            — краткая справка
```

## Просмотр истории в отдельном терминале

Можно открыть второй терминал и запустить клиент сразу в режиме истории:

```sh
./cchat --history
```

Затем введите номер сервера. Клиент покажет:

- сколько всего сообщений;
- сколько доступно кусков;
- список номеров кусков;
- первый кусок.

Внизу каждого куска есть приглашение:

```text
Кусок 1/2. Введите номер куска (1..2, 0 — выход):
```

Введите номер нужного куска. В одном куске 100 сообщений. `0` завершает
просмотр.

Для просмотра нужен локальный файл истории, созданный после входа в чат под
этим сервером. Клиент при входе скачивает полную историю с сервера и
перезаписывает свою локальную копию, поэтому после первого входа история
доступна и для офлайн-просмотра.

## Где лежат данные

Сервер:

```text
data/users.db          — аккаунты: ник, соль, PBKDF2-хеш пароля
data/chat.log.enc      — зашифрованная история общего чата
```

Клиент:

```text
~/.cchat/servers.tsv                       — добавленные серверы
~/.cchat/history/<название>_<hash>.enc     — зашифрованная локальная история
```

Файлы истории — обычные текстовые файлы, но содержимое сообщений в них
зашифровано. Формат:

```text
CCHAT-HISTORY-V1
CC1:<hex: nonce + ciphertext + tag>
CC1:<hex: nonce + ciphertext + tag>
...
```

Внутри расшифрованной записи хранятся ник, время и текст сообщения, поэтому
при просмотре истории видны ники и сообщения.

## Криптография

- SHA-256 и HMAC-SHA256 — собственные реализации на C;
- PBKDF2-HMAC-SHA256 (80 000 итераций) — хеширование паролей;
- ChaCha20 (RFC 8439) + HMAC-SHA256 — шифрование сообщений и файлов;
- случайные 96-битные nonce из `/dev/urandom`;
- отдельные ключи для направлений `клиент → сервер` и `сервер → клиент`;
- отдельный ключ для файлов истории;
- проверка MAC выполняется до расшифровки, сравнение тега —
  constant-time.

Все ключи выводятся из `SHARED_SECRET`, заданного в `.c` файлах. Это
**pre-shared key**, а не TLS. Ключ находится в бинарнике клиента, поэтому
схема подходит для учебного/доверенного окружения, но не заменяет
полноценный защищённый транспорт (TLS/Noise) для публичного интернета.

Если изменить `SHARED_SECRET`, старые зашифрованные файлы истории прочитать
уже не получится. Сервер и все клиенты должны использовать одинаковый ключ.

## Ограничения

- один общий чат на сервер (без комнат и личных сообщений);
- никнейм — до 32 байт, пароль — от 4 до 128 символов;
- одно сообщение — до 2000 байт;
- синхронизация истории при входе ограничена 200 000 сообщений;
- сервер хранит аккаунты и историю в локальном каталоге `data/` рядом с
  бинарником (запускайте сервер из каталога проекта).
